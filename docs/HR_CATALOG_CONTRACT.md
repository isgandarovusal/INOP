# Recruitment brand and workplace contract

Recruitment owns an additive catalog under `/api/hr/brands` and `/api/hr/branches`. The default brand keys are `kfc`, `pizza-hut`, `simit-sarayi`; names are KFC, Pizza Hut, Simit Sarayı. Defaults are read-only built-in metadata; reads do not seed or rewrite MongoDB. New brands have validated stable string keys in `RecruitmentBrand`. Creating a global label requires the existing `recruitment.create` **all** grant. It never grants access to a Job, Candidate, Application or Restaurant.

`RecruitmentBranch` represents a restaurant, central office, warehouse or remote workplace. Restaurant branches require a brand; office/warehouse/remote may be corporate and unbranded. Different locations can hold vacancies with identical titles. A branch uses server-set `createdBy`, `assignedTo`, `departmentId`, with the same existing recruitment own/department/assigned/all grants. Parent identity is immutable. Delete deactivates a branch and preserves history; inactive locations cannot receive new links. No scope rule is invented for the existing audit Restaurant model: its explicit-all fail-closed authorization remains intact. These HR locations do not backfill or expose audit Restaurants. Future reconciliation with real restaurant records needs an explicitly authorized mapping, not name matching.

Jobs add nullable `brandId` and `branchId`; omitted legacy values remain null. Create/change validates active brand, independently readable branch and matching branch brand. Reads decorate labels through a batch scoped branch lookup. An inaccessible branch label stays null. Applications retain independently authorized Job population, including the brand/branch references; a denied Job remains null. No global brand inference or mass legacy rewrite runs.

`GET /jobs?brandId=<key>&branchId=<ObjectId>` intersects filters with the existing Job scope. Catalog and job/application UI selectors preserve unset values. The later HR analytics package must use these same references and scoped datasets. Selection never replaces authorization.

New Mongo collections: `recruitmentbrands`, `recruitmentbranches`. Brand `_id` is unique. Branch `code` has a unique index; branch provenance and Job brand/branch fields have lookup indexes. Production index preparation belongs to the separately approved release procedure. No production DDL, seed, secret or deployment change is performed by this package. Existing branch links may remain when a location is deactivated; restoring a historical label is not a new access grant.
