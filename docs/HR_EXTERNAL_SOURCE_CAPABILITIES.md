## Concrete adapter interface / default-off receiver

Server-only `createSignedSource` accepts **approved backend relay** envelopes (not secrets in a public browser), binds to one approved existing HR actor through the private current-DB context and existing scoped Source sink. Signature covers version+source UUID+epoch milliseconds+v4 command UUID+SHA of exact original raw request body. Bounded JSON payload inside octet-stream contains only original file metadata/base64, explicit consent+approved notice version and optional approved vacancy reference. All extracted profile facts/permissions/actor/Job IDs are rejected; HR review creates the person later. Unknown/ambiguous/closed/foreign Job references remain review queue. Actual vendor schema adaptation is BLOCKED_EXTERNAL until real approved samples are known.

Additive `POST /api/hr/career-intake` is **disabled before its octet-stream body parsing** in the committed default profile. It uses its own approved signed-relay authentication; all other non-auth HR endpoints still require JWT. Headers: X-INOP-Source-ID, X-INOP-Command-ID, X-INOP-Timestamp, X-INOP-Signature. Content-Type application/octet-stream preserves exact signed JSON bytes and avoids the existing global JSON parser. It is not an activated public applicant portal, website form integration or real provider E2E. No secret may be placed in website HTML/JS. A first-party backend must forward the applicant's lawful consent/CV using its server secret; actual browser anti-abuse/captcha and first-party privacy notice require owner approval before wiring.
