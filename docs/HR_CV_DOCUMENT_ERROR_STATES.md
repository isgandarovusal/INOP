# CV upload/text parsing error presentation

Candidate editor parsing errors now store a fixed presentation key rather than a raw server/provider/request message. The displayed error follows AZ/EN/RU language changes without another API request or replacing an editable draft. Format/size, separate OCR processing, busy, timeout, missing endpoint, invalid request, unavailable service and network failure remain distinct. OCR copy reflects that optional OCR exists but requires configuration; text parsing does not imply OCR readiness.

A parsing 401/403 immediately masks the editor with the existing authentication/authorization state. Other auxiliary failures preserve the primary Candidate and draft. Current request sequence/cancellation, source-change proof handling and existing save contracts remain unchanged. Error feedback is an accessible alert. Parsing suppresses the global Axios raw-message toast; the editor emits one translated message. No backend scopes, routes, status contracts, original bytes, DB, provider/env or hosting settings are changed.

Tests use actual editor/XHR and deliberately intercepted error DTOs, not live provider failures. They verify nine error cases across three languages, zero language refetch, retained fields, no raw message display and two auth failures; inherited approval/OCR/AI/lifecycle cases stay passing. This narrow change does not claim all HR CRUD/backend validation text is translated; broader AUD-047 remains in progress. Original storage/recovery, malware, deletion/retention, ingestion and P11–13 release gates remain separate.
