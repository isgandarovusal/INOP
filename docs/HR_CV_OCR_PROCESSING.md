# P10C9 — optional bounded OCR preparation and real local evidence

This increment is **internal, disabled and unwired**. It does not change the current parse-only HTTP/UI, activate Native OCR/background workers or accept external CVs. `createOcrProcessing` reuses the existing queue with exact kind `ocr` and version `ocr-rules-1`. Original Candidate/role/source/lease/attempt/quota checks are inherited, including a current-authority check after private original IO before processing. Parse/AI profiles cannot claim or expose this result; rule-based parsing approval cannot accept an OCR job. Authenticated OCR diagnostics and explicit HR review/apply integration remain a separate increment.

## Engine and runtime

`createOcrEngine` is disabled by default. The server configures an absolute Tesseract binary/model directory and languages; the client cannot choose a command, path, arguments or model. Default supported languages are `aze`, `eng`, `rus`; all configured models must exist. Missing runtime/language returns explicit unsupported status, with **no automatic English fallback or fake OCR**. The existing PDF library renders from bytes, never a user URL. No dependency/lockfile, hosting environment, Render build/start or Docker configuration is changed. Hosted Native Tesseract and model installation/configuration remain unverified and require a reviewed supported runtime path before activation.

- Input: exact original SHA is checked by the queue; engine accepts bounded nonempty PDF bytes, maximum 5 MiB. Known PDF original metadata is required by the profile. DOCX is explicitly blocked for OCR rather than misinterpreted.
- At most three PDF pages; over-limit PDFs are rejected, never silently treated as complete. Page geometry and rendered pixel area are bounded before screenshot generation; desired width 1200, maximum 4 million pixels and 4 MiB PNG per page.
- PDF rendering runs in a private-copy Worker with eval/font/network URL use disabled, bounded V8 heap/stack and discarded stdout/stderr. Resource limits are **not an OS sandbox or absolute native/RSS cap**. This is not proof against all malicious PDF decoder cases; quarantine/scanning remains a separate prerequisite before real new intake.
- One active OCR per Node process, no additional hidden request queue; existing durable actor/global queue quotas remain separate across instances. Full engine deadline <=15s, aggregate text <=100,000 bytes. Renderer termination/native child cancellation/deadline prevent late result publication. Tesseract has `OMP_THREAD_LIMIT=1`.
- Native subprocess uses argument arrays with `shell:false`, a minimal fixed environment and no inherited provider/JWT/SMTP credentials. stderr is discarded; provider/decoder errors become fixed safe codes. Recognized text returns privately to the local structured parser and is never logged, sent to AI or stored as full rawText/job sections.
- Unique temporary directory 0700 and page PNG 0600; only its known file/directory is cleaned. Successful extraction requires cleanup. A cleanup failure returns `OCR_TEMP_CLEANUP_FAILED`, never silently succeeds. Cleanup also runs on deadline/late work and does not delete any native original, model, user file or existing directory.

## Review, unknowns and exact acronym evidence

OCR job results contain only known structured facts, original evidence and engine/version/languages/pages. Empty/null fields and empty arrays are omitted; a true extracted experience zero is retained. Provider is explicitly `tesseract-rules`, review status pending, all field confidence null (`uncalibrated_ocr`) and mandatory HR-original review warning. There is no claim that heuristic field confidence measures OCR accuracy and no automatic Candidate/status/score/hire/reject mutation.

The real Russian scan reproduced `HACCP` being recognized as visual Cyrillic `НАССР`. Only this exact bounded acronym family and established Russian `ХАССП` abbreviation map to HACCP in the **new OCR parser**. Raw token evidence is preserved and `ocr_acronym_review` is required; arbitrary near-matches, embedded substrings, names/contact/general prose are not normalized. The existing rules-2 parser and ATS scoring contracts are unchanged. This alias is a reviewable professional extraction, not a claim of certification or a reason to hire.

## Local prerequisites and evidence

Run `node Backend/scripts/prepareOcrTestModels.cjs` explicitly before real OCR regression. It downloads only official `tessdata_fast/4.1.0` AZ/RU/EN test artifacts to an owned `/tmp/inop-hr-ocr-models` cache, enforces 10 MiB/model and pinned SHA-256, refuses symlinks/incompatible existing files and never overwrites existing data. It is not imported at runtime, does not install a hosting binary or provision infrastructure. The 11.5 MiB model artifacts are outside Git; there is no secret/provider key or CV data in them. Tests also require local Tesseract and DejaVuSans font. No tests silently skip missing prerequisites or label mock output as real E2E.

`hrCvOcrProcessing.test.cjs` generates image-only PDFs and proves ordinary text extraction is empty before actual Tesseract. Three AZ/EN/RU fixtures preserve normalized +994 phone and Food safety/HACCP, raw evidence and unknown email; real queue/native private read tests cover admin/HR/own/department/assigned without changing the Candidate/original. This small synthetic corpus is not general OCR accuracy or hosted performance evidence. Russian input includes the English acronym; the configured Russian+English profile and exact acronym evidence are recorded, not an invented translation.

Separate synthetic adapter/process-shim tests cover absent models/runtime, cancellation/capacity/deadline, geometry/page/byte limits, subprocess environment privacy, private temporary permissions/cleanup/failure, mixed/foreign scope, source/role races, wrong-kind approval and unconfigured/no-text/DOCX status. Their output is not real OCR proof. `hrCvApproval` cleanup regression now observes the exact new file written by its own request; it no longer treats another concurrent test's generated file as a leaked upload. The original must still remain intact and exactly one rejected owned replacement must disappear.

Real storage/scan/recovery/retention and hosted runtime activation remain gates. Original pending source drafts, attachment/migration, ingestion, AI/OCR HTTP/UI and P11–13 are retained. No production operation, automatic download at runtime, provider/secret change, new hosting resource or push/deploy.
