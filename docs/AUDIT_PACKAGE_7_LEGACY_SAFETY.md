# Package 7: legacy analytics and resource safety

All legacy analytics paths remain mounted, with existing response envelopes/field names. They now share canonical direction/brand/restaurant/date validation and the same authorization scope as the new overview. Safety alias counts are canonicalized. Percent averages remain 0–100; overview remains explicitly out-of-10. Unscored values are excluded, genuine zero retained. Unknown averages are null, not fabricated zero: bundled legacy UI adapters are updated to show an em dash. External strictly-number clients must accept nullable averages before release. No threshold or historical score is recalculated.

Typed trends select the latest 12 groups then return chronological order. Explicit page/limit offers bounded windows. Audit list default stays an array; optional `format=page&page=1&limit=25` returns `{items,total,page,limit}` for new direction UI. Default legacy list consumers remain unbounded for compatibility; migrating them is future work. Invalid Mongo-style filters, directions, dates, page/limit and mismatched catalog relations return 400. API errors remain failures, never zero KPI data. No production speed benchmark is claimed.

Corrective action routing is mounted only after replacing weak assignment middleware with permission + parent data/direction scope. Creation ignores trusted client status/verifier fields and stores server actor provenance. Linked finding/execution must belong to the same audit. Parent locking serializes creation/status/closure; independent verification requires DB approval permission and forbids creator/responsible self-review. Findings and audit closure cannot pass unfinished actions. Legacy actions without trusted creator provenance require review before verification. No production grants are changed.

Source uploads validate supplied canonical fields; legacy unbound metadata remains compatible and restricted to global readers. A known canonical brand determines GFC directly from the code catalog, never from a filename. PDF/DOCX processing is explicit, bounded, CAS-claimed, freshly authorized after parsing, and produces only real extracted text/warnings. No template/questions/score is generated. Other formats return 415 for extraction. Deletion archives metadata; originals are retained. Raw upload access also checks source direction/organization. Internal paths are not returned. Render/production new source uploads are 503 until durable storage exists; legacy downloads remain authorized where bytes actually exist.

Remaining: approved durable source storage, stale-processing recovery policy, external nullable-score consumer checks, legacy unbounded callers, exhaustive old UI translation/CSS cleanup and full history stream consolidation. These are not declared complete.
