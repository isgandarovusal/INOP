# Versioned HR page API

New authenticated GET routes `/api/hr/v2/jobs`, `/api/hr/v2/candidates`, `/api/hr/v2/applications`, `/api/hr/v2/brands`, `/api/hr/v2/branches` preserve the original array routes. The page DTO's first schema version is `hr-page-v1`:

`{ version, items, page, pageSize, total, hasMore, nextCursor }`

Default pageSize 30, max 100; page 1–10000. Newest sort is createdAt DESC, _id DESC; Jobs/Candidates optionally support name ASC, _id ASC. A lookahead record determines hasMore. Scopes apply before count/sort/skip/limit, so counts include only the primary resource's authorized records. Lists support bounded escaped `q`, appropriate canonical status, Job brand/branch and Application jobId/candidateId filters. Invalid/inapplicable filters reject 400; database execution timeout is 503 with a retry/narrow-filter message.

An optional newest-sort cursor uses a creation-date/id tuple, avoiding duplicate records with equal timestamps. The opaque cursor is bound to user, current department/permissions, resource and filters/pageSize; stale or borrowed cursors reject 400. It is a pagination boundary, never an authorization token. Every request independently reloads current server authorization and intersects scope. Cursor mode uses page=1; ordinary page mode remains available, including legacy records without reliable creation dates. Changes to records during traversal can change the cohort; a cursor does not claim a transactional snapshot.

Projection includes a bounded 12-skill preview plus its true original count, Candidate experience (including null), and excludes Job description/checklists, CV extraction evidence/history and raw Application events/notes. App parent DTOs contain only independently readable Candidate id/name/role and Job id/title/status/brand/branch, without Candidate contact fields. Foreign parents are null; derived scores remain restricted. Application matching list DTO is a trusted summary (`summary=true`, empty criteria); the original authorized detail endpoint remains the evidence source. 08B switches HR consumers to pages. Score evidence is fetched from authorized detail only when explanation/review opens; denied or stale responses cannot retain a trusted score or write into a new permission context. Labels and skill previews are bounded; full HR review fields remain available through authorized detail, preventing an edit based on a truncated list DTO.

Application jobId/candidateId filters require the independently readable parent; unreadable and nonexistent IDs both return 404, so cohort counts cannot reveal a hidden parent. Application search joins independently scoped Candidate/Job names. A hidden name cannot contribute to result counts or be used as a search oracle. Candidate lookup accepts excludeJobId only for an independently readable Job, and anti-joins independently readable Application links, using a bounded lookup instead of an unbounded candidate-ID exclusion array. Hidden links are not disclosed; the existing unique Job/Candidate constraint still rejects a duplicate create. This does not grant application.read to a create-only user.

## Local DDL inventory

Add non-unique `{ createdAt:-1, _id:-1 }` and `{ scopeField:1, createdAt:-1, _id:-1 }` for each scopeField createdBy/departmentId/assignedTo on Jobs, Candidates and Applications. Applications add Job/Candidate-specific newest-page indexes and delivery-state/next-attempt indexes. Jobs add brand/branch/status/newest traversal. Existing indexes, including unique Job/Candidate pairs, are preserved.

Tests create and explain these indexes only in an owned loopback test database. The scoped Candidate index is explicitly hinted to verify that it can satisfy filtering and sorting with two records examined and no collection scan/sort. Actual unhinted plans and 0/5000/50000 data measurements belong to 08D; no large-data/live performance claim is made from this small fixture. Production DDL is not executed. Release preparation must inventory existing indexes, estimate size/build impact and explicitly approve the non-unique additive builds; no collection drop or seed is needed.

## Transition and remaining work

08A exposes/tests the backend page contract and indexes. 08B switches Jobs/Candidates/Applications lists, Job-specific applications/Candidate lookup and Candidate-specific matches to server pages. Legacy service methods remain for backward compatibility, but HR page components no longer call those array methods. Legacy unbounded list routes remain for compatibility and must be tracked until consumers migrate. The frontend will use scoped pages/search/lookups, lazy score evidence, cancellation and bounded rendering. Manual within-column order (AUD-064), parsing worker isolation and all benchmark evidence remain subsequent 08 increments. No item is declared complete solely because this contract exists.

08B details: 250 ms bounded search debounce; 30 rows/cards per page; filter/user/permission changes reset page 1 and cancel prior reads. Filters remain usable during loading/network/server errors, while 401/403 fail closed. Server totals, real zero scores and absent data remain distinct. Deletion/export failures retain primary list data; late mutations cannot reload or download in another auth/filter context. Job primary data loads independently of supporting requests, with separately paginated/retryable secondary sections. Full detail remains the edit source.

Optional catalog lookup opens paginated brand/branch/Job searches, making off-page choices discoverable without downloading entire catalogs. Shared brands retain the existing global catalog contract; branches and vacancies use recruitment.read scope. Selected values remain present even when their option page changes. Brand/branch labels on returned Job records use one batched lookup limited to the page's brand IDs. Brands keep immutable defaults first and custom names next; catalog cursor traversal is not exposed.

Application score/name order currently applies to the displayed page and is explicitly labeled. Global current-fingerprint ranking is a follow-up requirement, not claimed solved by sorting thirty records. Manual stage order, parsing-worker isolation, complete accessibility/localization, actual unhinted plans and benchmark evidence remain subsequent 08 increments.

08C4 adds the separate full-vacancy ranking read described in `docs/HR_RANKING_CONTRACT.md`. The historical 08B page-local ranking limitation is superseded for JobDetail; the multi-vacancy Applications table still explicitly labels page-local order. The new non-unique Job/id index is additive and remains a production DDL preparation item. Worker isolation is now tested in 08C2; manual order and 0/5000/50000 evidence remain open.
