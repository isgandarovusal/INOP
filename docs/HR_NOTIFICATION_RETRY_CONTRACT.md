# 10C1 — delivery monitoring and audited manual retry

Existing durable Application event SMTP outbox is reused; no new service/schema/index/hosting resource or SMTP secret. `POST /api/applications/:id/notifications/:eventId/retry` requires current server Application update AND read and independently readable Candidate/Job. Body is exactly expectedRevision, UUID commandId and bounded nonempty reason; actor/recipient/role/delivery/provider fields cannot be supplied. It checks current JWT/account/role/grants, parents, current latest Interview/Offered notification and cancellation before a bounded event-snapshot/revision CAS. Worker claims can change delivery without revision: matching the whole bounded event snapshot prevents overwriting a live claim/result. Concurrent commands have one writer; identical successful command replays after current authority checks without another event/write. Changed command/revision/history limit/stale/running/sent/skipped/manual limit return 409; missing parent/event 404, invalid command 400, invalid token 401, denied/revoked authority 403.

Only failed/blocked current notifications can be manually retried. If SMTP is unconfigured, 503 SMTP_NOT_CONFIGURED leaves the Application, workflow, score and event history unchanged; no false queue/send success. Authorized retry sets pending/reset current-run attempts, preserves prior attempt count, increments bounded manual retry count (maximum three), records a separate notification_retry event with actual actor/before/after/time/reason/revision/command hash and keeps original workflow actor/event unchanged. Normal worker maximum three attempts remains. Total known attempts are bounded to twelve across original plus three complete manual runs. Missing/corrupt current counters fail closed rather than claiming unknown past attempts are zero; pre-feature optional manual counters start at zero. No provider error/message, token, raw CV or SMTP recipient/credential is added to history DTOs.

The worker uses the server-recorded retryActor when present and checks that user's current active role/Application update and parent read scopes; it cannot fall back to the earlier actor if the retry actor loses authority. Finish/retry states preserve cumulative counters/retry identity. History whitelists only state/count/reason-code/timestamps, hiding claim token, retryActor and command hash. HR retry does not alter stages, interviews, candidate data, scores or hiring decisions. No synchronous SMTP request is made by the endpoint. Stable Message-ID supports receiver deduplication but SMTP is at-least-once: timeout may occur after acceptance, and manual resend may duplicate. UI warns before retry; no exactly-once/actual mailbox receipt claim.

Actual Application history UI shows AZ/EN/RU safe reason labels, real zero attempts, scheduled local-time retry and accepted-versus-unknown delivery. Unknown reason code gets a generic review label rather than displaying raw transport text. Only latest relevant, authorized failed/blocked notifications with a known revision offer retry; old history/cancelled workflow stays informational. Mandatory reason, pending/disabled state, conflict/reload and error preserve primary workflow. 401/403/404 reload the main resource to fail closed. AbortSignal plus route/actor/permission key prevent stale retry from refetching/updating another Application. Language produces zero requests; four widths retain accessible reason/buttons. Client checks supplement server checks.

Local evidence: `applicationDeliveryRetry`, `applicationNotifications`, `applicationDeliveryUI`, `applicationLifecycleUI`. Actual owned DB/Bearer routes, independent scope combinations, concurrent/event-worker CAS, replay, admin retry after original actor revocation, retry-actor revocation before send, parent-lookup grant change, no-SMTP primary preservation, manual limits, copy/lifecycle/responsive checks. SMTP transport is injected or unavailable; no external mail sent/real receipt proved. First backend fixture omitted required Job description; another tried setting a property inside null interview. Both were corrected and failed logs retained. Read-only UI negative baseline from c720a84 independently lacks all three translated reason labels; original open selector sampled the new text before switching locales, corrected to shared history readiness. Typecheck caught optional revision; retry now requires a known integer and never invents one.
