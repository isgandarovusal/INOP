# Immutable template revisions — package 3

Existing AuditTemplate _id is stable identity. Existing JSON uses draft/active/archived; these adapt to draft/published/retired. New POST /audit-templates/:id/publish, /draft, /retire use existing audit.template.update/all permissions plus audit management role. GET /:id/revisions is read-only and retains template direction scope. Real unique question IDs and canonical GFC/brand/direction are required for publication; no questions, weights or thresholds are invented.

Publish creates immutable AuditTemplateRevision content and changes active pointer in one transaction. Draft editing uses optimistic version checks. Concurrent publication yields one winner; the second sees 409. Published/legacy-active templates reject in-place editing. Explicit draft operation makes a new editable working copy on the stable identity, leaving every old revision unchanged. Retirement preserves content and historical references. DELETE template archives rather than orphaning revisions. Legacy active templates remain readable and can be explicitly adopted/published after review; no startup revision/backfill exists.

Verified Audit creation resolves server-side active revision against restaurant brand/direction, stores its reference/snapshot, and locks the active template in the publication transaction. Client revision/snapshot are discarded. Execution binds the Audit revision, even after retirement; unrelated checklist is rejected. Execution UI uses stored immutable snapshot and never fetches a mutable current template to alter historical questions. Unversioned executions retain stored answers and display a legacy warning; they are not silently rebuilt.

MongoDB validators and unique {templateId,revision} index are migration preparation only. Production autoIndex stays off. Publication serializes on the template and _id identities while migration is pending. Mongoose immutable hooks are not a defense against raw driver/out-of-band writes: review DB validator/write privileges separately. No production collection/index/backfill performed.

Legacy POST active adapter publishes only for management, after canonical review; a failed publication can leave a safe unpublished draft, never a partial published revision. API callers should use draft then explicit publish. Old mutation clients receive 409 for published content and must start a draft. This is intentional protection, not a silent historical change.
