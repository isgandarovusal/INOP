# Outlook durable sink / checkpoint —11B

Default-disabled server-only `createSync` uses approved fixed tenant+mailbox UUIDs and one existing designated HR actor. It is not mounted as a public API or started at boot. It requires current JWT + candidate.read/create on every step; actor/department are locked to the mailbox checkpoint (no implicit ownership migration). Actual Graph adapter/mock evidenceMode must agree. Other HR workers/mailing/task profiles are unchanged.

Two collections, explicit unique DDL (autoCreate/autoIndex=false, no TTL): `hrgraphsyncs` hr_graph_mailbox_unique `{mailboxKey:1}`; `hrgraphreceipts` hr_graph_attachment_unique `{identityHash:1}`. Source's existing unique/quota indexes are also required by its sink. Cursor, opaque identity, private source receipt and origin metadata are hidden from health output. No production DDL/migration is run.

One delta page/run (<=10messages), attachment pagination <=10pages/10items/message, max50s synchronization/60s compare-and-set lease,3 consecutive failures then blocked. Source commands use existing bounded queue/quota and immutable object identity. A new worker may reclaim expired lease; late worker cannot commit a cursor. Current actor/role/JWT is rechecked after every provider/storage boundary. No cursor advance until every supported original has a durable Source acknowledgement or durable unsupported-file receipt. Lost acknowledgements replay the same stable Source command; no duplicate object/Candidate write or destructive compensation. Deleted-mail delta never deletes Source/Candidate/Application/original. Unsupported inline/reference/oversize/non-CV types are recorded as skipped, not falsely parsed.

`enqueueApproved` is a server-only Source interface; public multipart Source route continues calling plain `enqueue` and never accepts privileged provenance from body. Private immutable origin stores only approved source enum, SHA identity, receivedAt, exact mapping outcome/optional Job ID. No email address, subject, body or token is stored in origin. Conflicting replay origin is409. Explicit approval preserves source.key/receivedAt into Application. There is no automatic Candidate/Application creation or HR decision.

Vacancy mapping: approved configuration references `[A-Z0-9_-]` and/or exact recipient address, combined when both present. Token boundaries prevent GFC_JOB_1 matching GFC_JOB_12. Exactly one mapped Job must currently be Open and readable under its independent recruitment.read scope. Ambiguous/unmatched/closed/foreign Job => no Job assigned; source still goes to private HR review. Company must provide mappings; code does not infer vacancy from similarity or website. HR must explicitly choose/confirm a current accessible Job; UI hint/source-review integration follows11C.

Health state/codes, consecutive attempts, acknowledged/skipped counters and last success/failure dates are sanitized only; no credentials/cursor/subject/contact/facts. `retry` waits60s; authorization/scope/malformed-provider/page-limit or exhaustion => blocked. No auto rebaseline/clear cursor/whole-mailbox replay/repair or account reassignment. 410 delta invalidation and provider-specific cursor formats need real company-owned mailbox tests and deliberate repair procedure; P11-020 remains BLOCKED_EXTERNAL. A failure never triggers DB/original deletion.

Actual Mongo + private Source writer/parser/explicit approval are tested with synthetic Graph and scanner/object store, not Microsoft, antivirus or durable provider certification. Real SMTP/provider/durability/privacy/backup/setup gates remain. Activation/binding, scoped hosted health and operations UI are not falsely declared available.
