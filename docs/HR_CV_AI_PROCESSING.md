# P10C8 — durable professional AI review profile

`hrCvAiProcessing.service.createAiProcessing` is an **internal profile, disabled by default**, reusing the existing Mongo CV processing queue. No route, Native worker flag, external permission, credential or automatic AI request is activated. The current synchronous explicit AI review UI/API and parse-only processing HTTP/UI retain their contracts. The new durable AI status/start/review UI is a separate remaining integration step; this foundation does not complete P10-010 by itself.

## Contract and compatibility

- Kind `ai-review`, immutable `taskVersion:ai-professional-1`; actor/parent/source/parser version are included in the idempotency context. The task version is persisted and query/claim filters require the exact profile. An old-version job is not silently executed with a different handler. No legacy parse row is backfilled or requires a new taskVersion field.
- Existing parse get/list/retry/worker only resolve kind `parse`. Default HTTP enqueue still rejects AI/OCR kinds. AI and parse reservations share the existing unique actor/global queue slots and three-attempt bounds; new kinds cannot obtain an extra hidden capacity pool. Current independent read/update, original/retry actor, revision/timestamp/original fingerprint and exact SHA remain required.
- Exact existing queue DDL must be present; no new index, startup DDL, migration or collection is applied. Future extra kind/query indexes require measured evidence, not this increment.
- Original bytes are authorized and hash-verified internally. Current source and original/retry actor are checked **again after original IO and before any external task**, then after task completion. No external provider sees raw original bytes, contact information, private key/path or entire review metadata from this profile.
- The existing professional-evidence builder permits only bounded literal same-field professional quotes and removes known name/contact/protected/sensitive input. This conservative filter is not a general PII detection guarantee. External CV review still requires existing explicit `HR_AI_CV_REVIEW_APPROVED` and provider configuration/approved budget. Provider keys/configuration are not set by this work.

`result` is private/select:false and at most 128 KiB. It contains `requiresApproval:true`, `parserVersion:ai-professional-1`, professional evidence IDs/quotes, the schema-validated proposal and source-bound provenance. Exact provider/version, model/mode/context hash, literal evidence, uncertainty and no protected criteria/decision are validated before persistence. `mock_test_only` stays visible and is never converted to `live`. No hiring/rejection, Candidate edit/status, application scoring/status or candidate-global workflow is performed. Parsing approval remains kind/rules-2 only, so AI evidence cannot impersonate a parsing approval receipt.

Missing provider/approval gives persisted blocked `AI_NOT_CONFIGURED`; absent eligible evidence gives `AI_REVIEW_CONTEXT_REQUIRED`. Invalid/biased/forged proposals give blocked `RESULT_INVALID`, never a static result. Other provider outages use the existing bounded persisted retry policy; fixed codes omit raw error payloads. Provider-level bounded retry/cost/rate controls remain in the P09 adapter; total queue attempts are three, not unlimited. Requests remain internally cancelled at deadline; late ignored provider answers cannot publish after cancellation/lease loss.

## Evidence and remaining work

Five permitted scopes, foreign/mixed negative cases, parse coexistence/cross-kind isolation/shared quota, old task version, zero synchronous provider calls at enqueue, unconfigured/unsupported, protected/forged proposals, original-IO revocation before provider send, provider-wait source races, stale read suppression, outage/recreation/deadline and unchanged Candidate are covered. No real AI key/request, malware scan, storage durability/recovery or hiring outcome is tested or claimed.

Remaining P10 work includes current-source authenticated AI queue endpoints/diagnostics and explicit UI review, actual OCR, source drafts/attachment, ingestion and privacy/retention/orphan reconciliation. Real AI E2E remains BLOCKED_EXTERNAL (P09-023), alongside actual storage/recovery/SMTP/Graph/source access. No push/deployment or production migration/secret/resource operation.
