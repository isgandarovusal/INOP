## Reused contracts and implementation boundaries

Existing duplicate-history pagination, both-record access checks, revision fingerprints, user-scoped RAM drafts and denial-triggered eligibility refresh are retained. New metadata is server-derived; client-supplied evidence/merge commands remain rejected. Comparison uses the same independently authorized records; no extra initial Recruitment request or N+1 API loop. Current review references are never inferred from caller flags. Newly recorded evidence is additive; older consumers continue to read ordinary decisions.

Audit linking lives outside finalized inspection content. No exception to original answers/scores/checklist/evidence/history immutability is needed. Only the new child gets its creation History. Links are returned only when **both records are currently readable**. POST independently requires direction-specific create permission; read access alone cannot create. New records inherit reference subject/location/brand/direction only, not old answers, scores, photos, findings, CAPA, assignment or approval. Existing assignment/draft/finalization/verification workflows handle the child. Legacy unversioned closed records remain ineligible until trusted catalog provenance is reviewed; no catalog is guessed.

A separate bounded metadata GET is added on Audit detail (plus explicit pagination/Refresh); Dashboard and initial Recruitment list request counts are unchanged. Native antivirus adds one post-scan version probe; real engine overhead was not measured. No performance improvement is claimed for that security check.

HR/Service 0/0.5/1/N/A, justified full-catalog Standard results, separate HSE object aggregates and CAPA independent verification/idempotency remain unchanged. There is no new scoring, automatic identity merge, automatic hiring/rejection, external messaging or sensitive offline persistence.
