## Fixes and contracts

- `candidateDuplicate.controller.js` and `CandidateDuplicateHistory.tsx`: both candidate records must be independently readable before history can be returned. Historical records do not restore access to archived/reassigned profiles. History/current decisions are derived from current fingerprints, not caller flags. Match pagination and totals use the same scoped predicate. Current per-pair review aggregation no longer drops a valid decision merely because another pair filled the old 100-row history window.
- `CandidateDuplicateReview.tsx`: bounded on-demand requests, scoped in-memory drafts, failed refresh recovery, and eligibility refresh after 401/403/404/409. No automatic retry of a denied mutation and no persistent browser PII storage.
- `hrAnalytics.controller.js` / `RecruiterTeamWorkload.tsx`: no new initial Dashboard or overview request. Authorized Operations view loads a separate bounded team aggregate; paging does not rerun the expensive score scan. Names require independent User access. Grouped row scope is explicitly `assigned-to-recruiter`, not `assigned-to-me`. Global Analytics Refresh and the report's own Refresh are both effective. No N+1 HTTP/database application loop.
- `recruiterWorkload.service.js`: active next-action kinds are required for overdue counts. Calendar/date windows and deterministic ATS are unchanged.
- `auditAction.controller.js` / `auditAction.model.js` / `HRAuditActions.tsx`: optional command identity and server-computed body hash. Existing Audit write lock and transaction serialize concurrent identical commands. First creation returns 201, replay returns 200, changed body returns 409. Private command metadata is omitted from responses. Closure checks remain before writes/replays; legacy callers without a command remain compatible. No new production index/migration required for CAPA replay.
