# Optional durable professional AI review

AI remains separately opt-in: `HR_CV_AI_PROCESSING_ENABLED=true` enables the existing Mongo task profile/worker and authenticated kind `ai-review`; it does not approve external CV processing or configure a provider. The existing `HR_AI_CV_REVIEW_APPROVED`, provider/model/key, price/budget/rate/timeout settings remain independent release gates. There is no runtime mock switch. No environment/secret/hosting/resource configuration is changed by this code. Missing approval/provider is an explicit blocked AI_NOT_CONFIGURED result, not static skills or fake success.

Default parse URLs/payload/history remain compatible. Optional `?kind=ai-review` history is metadata-only, capped at 20. Child kind/version is resolved server-side with the owning Candidate; an obsolete child returns PROCESSING_JOB_UNAVAILABLE rather than masking a still-authorized primary Candidate. Disabled profile, DDL/capacity/source conflicts and independent Candidate read/update/current JWT/role/assignment boundaries retain the existing contracts. The shared queue limits, actor slots, leases, lifetime attempts, original-creator and retry-actor authorization apply equally. Configuration repair retry is explicit/idempotent and uses remaining lifetime attempts. Insufficient professional context or invalid/protected/unsupported output stays blocked with no persisted review result.

Every submission is bounded professional evidence from the exact original. Name/contact/filename/URLs/raw CV/protected traits/unknown sections are excluded. Quotes are untrusted data; provider tools are disabled and structured literal same-field evidence references are validated. Current source/authorization is refreshed before and after awaited IO/provider work. Rule-parser evidence retains existing explicit-review behavior. OCR evidence is eligible only after source-bound server HR confirmation with matching original hash/OCR receipt; pending OCR and recursively AI-derived evidence fail closed. This conservative filter is not a general PII detector, and real organizational processing consent remains required.

The durable result preserves provider/model/mode/context hash, professional quotes, proposals/reasons/uncertainty and source/task version. Unknown fields are omitted; numeric zero stays zero. Field confidence is null (model self-confidence does not establish statistical accuracy). Model proposal confidence remains separate in the private job for human interpretation. The actual UI shows MOCK TEST for injected test transports, clearly distinguishes real proposals from finalized HR facts, displays reasons/evidence, and never represents local stub output as live AI verification.

Loading is read-only. Apply creates an editable draft, merges AI-proposed skill/language/certificate lists with existing human facts, and resets confirmation. Explicit HR save uses one current-source Candidate CAS; server evidence/provenance and approval actor/time/result/profile/source hashes are authoritative. Client provenance is ignored. Optional provider provenance has no default/backfill/index/migration. AI never changes ATS decisions/statuses, creates Applications or automatically hires/rejects. Normal human fact updates can invalidate old matching scores through the existing update behavior.

Local evidence uses actual owned loopback Mongo/HTTP/Chromium and the real provider adapter with deliberately synthetic transport. Real provider key/receipt, hosted worker behavior, private original durability/recovery, malware scanning/retention and real CV intake are not verified. Original bytes are retained; no push/deploy/production DB/DDL/secret/resource operations.
