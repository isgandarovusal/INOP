# Approved HR background identity / worker preparation —11D

Background synchronization cannot safely retain an employee browser JWT indefinitely. Server-only `createActorContext` (default off, explicit approvalRecorded and fixed existing actor ObjectId required) creates a private WeakMap request identity. It holds ONLY the actor ID: no JWT, role claims, credentials, source facts or privilege grant. Each authority boundary re-reads active User/current department/active Role permissions from Mongo, then existing independent resource scope helpers decide access. No new User/Role, additional permission or access scope is invented. Company must approve the designated existing actor before a hosting binding is added.

Only Node server adapter construction may create a context; HTTP JSON/headers/req.user/object copies cannot recreate WeakMap identity. All ordinary API routes still run the unchanged verifyToken middleware first and enforce existing JWT expiry/revocation. This narrow internal producer identity is never a replacement public authentication method. Authorization tests include forged HTTP/body/header contexts, inactive/demoted actor, revoked candidate grants and actual Source enqueue/parse/current read. Application approval remains a separate explicit currently authenticated HR action; worker never auto-creates Candidate/Application or makes decisions.

`createWorker` is also default-disabled and not called by app startup. At most one tick runs per instance, one approved mailbox page per tick in round-robin, <=10 configured mailboxes, minimum60s per-mailbox polling, <=2 Source tasks/tick. Existing persisted Mongo leases, Source quotas/3 attempts and Graph transport IO deadlines remain the real cross-process bounds. A Graph outage does not block independent Source parsing. Per-tick failures become sanitized health state; no error body, token, mailbox IDs, source/CV facts or cursor is logged. Owned stop clears only its timer, prevents later parsing and waits current bounded work; it does not delete/reset queues. Configured adapter methods must honor existing deadlines; synthetic noncooperative mock completion is distinct from hosted service behavior.

No global boot interval, env loader, native Render runtime modification or external request is introduced. Activation remains BLOCKED_EXTERNAL: approved tenant/actor/mailbox/job mapping, real private durable store/current AV/signatures, explicit DDL, privacy/retention, provider access/recovery evidence and hosted worker lifecycle. A future native Render binding can reuse the process plus existing Mongo; no extra cluster/queue/service is created. Backend code alone does not establish a persistent Render worker SLA or uploaded-file durability.
