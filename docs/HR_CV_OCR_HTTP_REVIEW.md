# Optional OCR HTTP, worker and explicit HR review

Default processing remains `parse`. OCR is a separate trusted task profile, off by default. `HR_CV_OCR_ENABLED=true` opts in to both the authenticated OCR profile and its existing Mongo worker; `HR_CV_OCR_DATA_DIRECTORY` optionally sets a server-owned absolute language-model directory. No environment values, runtime packages, models, DB indexes or hosted settings are changed by this implementation. Native Render must separately provision a supported Tesseract executable and AZ/EN/RU models; local availability does not verify hosting. No automatic model download occurs at runtime.

Existing private Candidate routes retain their URLs, Bearer auth and independent resource scope. POST `/api/candidates/:id/processing` accepts the existing `parse` kind or explicit `ocr`, with current `expectedHash` and `expectedRevision`. GET history without a kind remains parse-only; `?kind=ocr` is the optional OCR history. Unknown kinds return 400. Child detail/retry selects its owning persisted kind server-side; a client cannot reinterpret a sibling job/profile/version. Disabled profile returns 503 PROCESSING_DISABLED; missing shared queue DDL returns 503 PROCESSING_QUEUE_NOT_READY. Optional bounded task-kind/version/queue indexes must be prepared separately with existing review gates. No automatic startup DDL/backfill or migrations.

Only successful exact-source results can enter the existing Candidate editor. The detail selector chooses a profile explicitly and does not start processing on page open, StrictMode remount or language change. Status/history requests are bounded and separate from primary Candidate data. Source/auth/route changes cancel or discard old results; auth/parent loss hides private state, auxiliary failures retain the primary editable draft. Server and UI label OCR as OCR plus rules, not AI; field confidence stays null and every recognized fact requires human verification against the original.

Loading evidence is read-only; Apply copies known facts into a draft, preserves unknown/manual fields, and resets confirmation. Saving requires an explicit HR confirmation, current source/revision/job timestamp, fresh JWT/current independent Candidate read/update and one source CAS. The server derives provenance from the persisted result; client extraction/confidence/provider/receipt are not trusted. No decision/status/Application mutation is performed by OCR. The existing successful Candidate update may invalidate old matching scores when human facts change, as before.

Repair retry supports a missing original/storage and OCR runtime/language configuration failures. It is explicit, retains creator and current retry actor authorization, exact source, immutable task version, UUID command replay, lifetime three attempts/two manual retries and global/actor queue bounds. Invalid/oversized/no-text documents are not blindly retried. A changed source requires a new source-bound job, not reusing old evidence.

Evidence: owned loopback Mongo and HTTP, real Tesseract scanned PDF extraction and actual browser editor/approval; synthetic negative dependency tests are labeled separately. Real hosted runtime, original-object durability/recovery and production intake readiness remain unverified/BLOCKED_EXTERNAL. No push/deploy, secret changes, original deletion, provider/resource creation or production DB action.
